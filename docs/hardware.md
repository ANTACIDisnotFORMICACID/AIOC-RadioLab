# 双手台台架与射频测试流程（待用户执行）

```text
电脑 RadioLab ── AIOC USB Audio OUT + 串口 PTT ── 手台 A（TX）
                                                   │
                                                合规 RF 链路
                                                   │
电脑 RadioLab ← 独立录音输入 ← 安全电平匹配/麦克风 ← 手台 B（RX）
```

1. 先断开或使用假负载，在不辐射的条件下确认 AIOC 固件版本、串口空闲时 PTT、打开串口瞬间 PTT、DTR/RTS 控制和关闭后的释放。旧固件的 DTR 逻辑不同，当前代码仅接受经验证的 1.2+。
2. 运行 `radiolab devices`，分别选择 AIOC 的 TX **输出**、第二台手台的独立 RX **输入**、AIOC 串口，填写 `config.toml`；GUI 可用“刷新设备”后从列表选择，再点“编辑配置”保存 TOML。不能把 AIOC 自身输入当成第二台手台的接收证据。保存配置不会按下 PTT。
3. 不接射频链路，先用 `radiolab text encode 'HELLO WORLD' -o runtime/hello.wav` 和 `radiolab text decode runtime/hello.wav` 确认离线闭环。使用 `radiolab check --config config.toml` 检查字段。
4. 由操作者核对本地许可、合法频率、呼号、信道占用、手台模式和低功率设定；从低电平短音频开始校准，监看失真、反馈、过热和端点丢失。
5. 在第一个 PowerShell 窗口用手台 B 的独立音频路径启动 `radiolab receive record --seconds 45 -o runtime/rx.wav --config config.toml`；确认录音正在进行后，在第二个窗口由操作者显式运行 `radiolab text send 'HELLO WORLD' --on-air --config config.toml`。不要让录音窗口的默认输入误选成 AIOC 的软件回环。
6. 对录音运行 `radiolab text decode runtime/rx.wav`，保留原始 WAV 和配置摘要。只有 CRC 通过且确认录到的是手台 B 音频，才记录真实链路成功；失败则记录信号路径、PTT、录音电平和错误原因。

一个 AIOC 不提供完整双向 ACK。软件尽力在异常时释放 PTT，但无法处理 USB 断电、进程被强杀或硬件卡键等全部物理故障。

V0.2 GUI 也提供真实发射入口，但仅在上述无辐射台架与合法操作确认后使用：在窗口中分别选择 TX 输出和 PTT 串口，指定同一设备的 `config.toml`，勾选本次确认，再审阅逐次弹出的发射摘要。取消对话框不会打开串口；“停止发射”会请求音频停止和 PTT 释放。此 GUI 路径目前只有 FakeAudio/FakePTT 自动化证据，不能据此记录真实 RF 成功。

## 常见问题

- `devices` 没有 AIOC：先检查 USB 枚举和固件，重新运行设备列表；不要沿用之前的编号或 COM 口。
- `check` 显示设备就绪仍不能发射：该命令检查配置、音频格式支持和串口枚举，不打开串口，也不能代替真实接线、打开瞬态和合法频率确认。
- 录音电平很低或接近削波：检查手台 B 的音频路径和输入增益，保留原始 WAV。电平有读数不等于收到有效帧。
- 文本解码提示找不到有效帧：检查是否录到了手台 B、是否有足够首尾静音、音频是否过载；只有 CRC 通过才显示成功消息。
- SSTV 图像颜色/行同步异常：保留原始 WAV 与解码日志，用独立解码器复核 VIS、颜色和行同步；内置自解码通过不等于跨软件或射频互通通过。
- PTT 未如预期释放：立即停止测试并手动断开/处理设备，保存故障记录；软件无法替代物理检查。
- 提示“PTT 释放状态不明”时，本进程会拒绝后续发射；先在无辐射条件下检查手台和串口是否卡键，排除故障后再重启应用。
- 提示“旧发射清理线程未结束”时，软件暂时保留发射互斥，拒绝新的发射；先确认手台 PTT 已释放并检查音频设备，待清理结束。若设备操作持续卡住，停止测试并重启应用，不要反复尝试空中发送。
